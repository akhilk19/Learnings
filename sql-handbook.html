Part 1 — Set up Docker and MySQL

Environment: macOS + Docker Desktop + MySQL 8.4. You only need to do this setup once.

1. Verify Docker Desktop

Install and open Docker Desktop for Mac. Wait until Docker reports that its engine is running. Then open Terminal:

docker --version
docker compose version
docker info

What these commands mean: docker --version checks the CLI; docker compose version checks Compose; docker info confirms the daemon is reachable.

2. Create a project folder

mkdir -p ~/sql-learning
cd ~/sql-learning

3. Create a Docker Compose file

Create a file named compose.yaml in that folder:

services:
  mysql:
    image: mysql:8.4
    container_name: sql-learning-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: LocalRootPass_ChangeMe
      MYSQL_DATABASE: employee_management
    ports:
      - "3306:3306"
    volumes:
      - mysql_learning_data:/var/lib/mysql

volumes:
  mysql_learning_data:

For local learning, this password is a placeholder. Do not reuse it for a real system or commit real credentials to source control.

4. Start MySQL

docker compose up -d
docker ps
docker logs -f sql-learning-mysql

Wait until the logs indicate that MySQL is ready for connections. Press Ctrl + C to stop following logs; this does not stop the container.

5. Connect through the terminal

docker exec -it sql-learning-mysql mysql -uroot -p

Enter the root password from compose.yaml. You should see the mysql> prompt.

6. Select the learning database and inspect it

SHOW DATABASES;
USE employee_management;
SELECT DATABASE();
SHOW TABLES;
EXIT;

USE selects the default database for subsequent statements in that MySQL session. EXIT leaves the MySQL client, not the Docker container.

Useful Docker commands

CommandPurpose
docker psList running containers
docker stop sql-learning-mysqlStop the container
docker start sql-learning-mysqlStart the existing container
docker compose downRemove the container/network; keep named volume data
docker compose down -vAlso deletes the named volume and database data — destructive
docker exec -it sql-learning-mysql bashOpen a shell inside the container
Docker mental model: an image is the packaged template; a container is a running instance; port mapping exposes MySQL on your Mac; the named volume keeps database files when the container is replaced.

Part 2 — Create our two-table database

We will use the same small dataset throughout the course so that each new SQL concept builds on familiar data.

1. Understand the relationship

A department can have many employees. Each employee belongs to one department in this simplified model.

department_id — primary key1 ───── manydepartment_id — foreign key
department_nameemployee_id — primary key
name, salary

Primary key: uniquely identifies a row. Foreign key: enforces that a referenced department exists. This is referential integrity.

2. Create the tables

USE employee_management;

CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(80) NOT NULL,
    salary DECIMAL(10, 2) NOT NULL,
    department_id INT,
    CONSTRAINT fk_employee_department
        FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);

3. Insert departments first

INSERT INTO departments (department_id, department_name) VALUES
(1, 'Engineering'),
(2, 'HR'),
(3, 'Finance'),
(4, 'Marketing');

Part 4 — DBMS concepts and internals

These ideas explain what the database is doing beyond the SQL syntax.

Relational modelling and normalization

  • 1NF: each column stores an atomic value; avoid repeating groups.
  • 2NF: be in 1NF and remove partial dependency on part of a composite candidate key.
  • 3NF: be in 2NF and remove transitive dependency of non-key attributes on candidate keys.
  • Denormalization: deliberately duplicate or precompute data for read performance, accepting consistency costs.

Transactions and ACID

  • Atomicity: all-or-nothing transaction outcome.
  • Consistency: constraints and rules remain satisfied.
  • Isolation: concurrent transactions are controlled according to the isolation level.
  • Durability: committed changes survive failures within the database's guarantees.

Indexes and query execution

Indexes can reduce the amount of data scanned, but consume storage and add write overhead. MySQL commonly uses B-tree indexes for ordinary InnoDB indexes. Use EXPLAIN to inspect the optimizer's plan; do not assume an index will always be selected.

Concurrency and isolation

Know dirty reads, non-repeatable reads, phantom reads, lost updates, locks, deadlocks, and the MySQL isolation levels. A transaction's actual behaviour depends on the isolation level and engine.

Database architecture and modern systems

  • Client/server architecture, connection pooling, buffer pool, redo/undo logs, binary logs.
  • Replication, backups, point-in-time recovery, failover, partitioning and sharding.
  • OLTP vs OLAP, row stores vs column stores, data warehouses.
  • Relational vs document, key-value, graph and wide-column NoSQL databases.
  • CAP theorem as a distributed-systems trade-off under network partition; consistency models and eventual consistency.

Final learning checklist

Learning note: examples target MySQL 8.4. SQL dialects differ; check the documentation when moving to PostgreSQL, SQL Server, Oracle or another database. Always practise destructive statements on disposable data first.
